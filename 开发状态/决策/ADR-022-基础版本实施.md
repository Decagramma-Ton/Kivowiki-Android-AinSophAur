# ADR-022 · 先交付基础与系统能力

日期：2026-09-07。状态：已执行。依据：站长本次明确要求优先完成框架、真实首页、账号与设置，完整业务模块后续开发。

原设计 P0 同时要求角色搜索、档案、OGG、Spine、3D 和千图样例。这次将验收闭环调整为首页 → 公告/文章原生阅读 → 本地收藏 → 再次打开 → 设置持久化。媒体验证仍保留在后续专项，不删去原需求，也不为了勾选 P0 提前引入重型运行时。

采用 7 个实际 Gradle 模块，尚未实现的业务以 Portal 入口表示。这样既可操作，又不创建几十个没有行为的空 feature。跨模块影响是 app 负责当前系统页面装配；以后业务开始时再提取对应 feature，不复制主题、网络、账号与存储。

账号依据公开网页可核实的协议实现，可测试流程走本地替身；真实用户资料成功样本缺失仍如实记录。公开 API 与认证共用连接资源，令牌通过方法参数传递，禁止全局拦截器注入，以免图片/外域请求携带凭据。

正式身份未确定时采用 `wiki.kivo.app.preview` 与测试签名，只交付本机内部验收包。未来正式身份可能不同，应先提供本地资料迁移方案；不得用当前测试密钥直接公开发行。

验证证据：当前构建、测试、实际截图和 APK 检查见 artifacts/验收报告.md。可回退边界：保留旧设计作为后续范围基线；本次不迁移已有网站数据、不修改服务器、不接触正式安装身份。

本记录细化 ADR-005/006/009/017/018/020 的本期落地，并调整原 P0 执行顺序；不撤销 ADR-012 至 ADR-016 的后续媒体目标。

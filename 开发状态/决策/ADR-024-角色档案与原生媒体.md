# ADR-024 · 角色档案与原生媒体

日期：2026-09-07；状态：本期采用，实际验证范围见 0.3 报告。

## 问题

角色数据存在多类型、多 EX、衍生技能、关联角色、NPC 模板与多语言空值。鉴赏资源还包括 Spine4.2、GLB2 和旧 OBJ。直接扩充通用 Reader 字符串或包裹官网页面会丢失领域交互、资源生命周期与原生访问能力。

## 决定

创建专用 `feature:character`，以 `CharacterProfile` / `BattleProfile` 等类型保留完整结构；复用公共 API / 缓存和内容块，保留逐字段翻译。通用 Reader 继续服务其他实体。

创建 `core:media` 作为后续媒体模块可复用的单一基础层。Spine 使用锁定 4.2.12 的官方 Drawable 和 Canvas 渲染器，自行管理 Choreographer。理由是高层 SpineView 默认一直 postFrameCallback，难以让暂停／省电真正停止绘制。

3D 使用 Filament 1.75.1 / gltfio，GLB 保留蒙皮与动画，OBJ 在有界沙箱里转成标准 glTF。不同时维护 Unity、Three.js WebView 或另一套 3D 引擎。模型按网页已核对的规则使用 unlit 游戏贴图、绑定 HaloRoot，并以共享边划分嘴部几何。遇到未识别材质保持源模型，不凭角色名称硬写处理。

图片放大使用系统分区解码；音频与技能视频使用同一 Media3 1.11.0 实例。没有后台音乐服务；后续留声机若需要后台播放，应扩展该协调器及 MediaSession，不新增竞争播放器。

导出使用 SAF + 原生 PNG / MediaCodec，提供 5 秒无声预览，限制像素与帧率，允许取消。大厅事件到音轨缺少契约，因此不推断同步声音。

## 成本与边界

原生图形依赖增加包体，需检查实际 APK、ABI、ELF 16 KiB 对齐以及 R8 后运行。模拟器不替代 ARM 手机 GPU、温控、低内存或混合透明效果验证。

缓存文件名包含元数据 URL 指纹，但 API 没有内容 hash / ETag manifest；同 URL 替换素材时可用“重新下载并重试”清除该资源包。不得把 URL 哈希写成源文件内容校验和。

Spine 运行时许可独立于站内素材许可。完整原文随包保留，公开发行前核对有效授权。没有为消除提示而更改系统安全设置、签名身份或后端。

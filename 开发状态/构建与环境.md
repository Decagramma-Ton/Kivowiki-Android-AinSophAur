## 给第一次验收的人

双击工程根目录的 `电脑验收.cmd`，直接使用已构建 APK。首次会打开专用 Android 模拟器，鼠标点击、拖动即可操作。完整说明见 [验收说明](../artifacts/验收说明.md)。预览不需要重新编译，也不连接服务器后台。

如需关闭专用模拟器，先关闭应用窗口，或在本工程终端执行：

```powershell
powershell -NoProfile -File tools/stop-preview.ps1
```

此命令只接受名为 Kivo_Archive_Phone 的模拟器，不操作真实手机或其他模拟器。

## 重新构建

在 `App项目开发` 打开 PowerShell：

```powershell
# Release + R8 + 资源缩减，成功后复制 APK 并计算 SHA-256。
powershell -NoProfile -File tools/build.ps1 -Target Release

# 开发用独立包名，可与验收包共存。
powershell -NoProfile -File tools/build.ps1 -Target Debug

# 本地逻辑测试、Debug/Release Lint、Release 构建与交付复制。
powershell -NoProfile -File tools/build.ps1 -Target Verify

# 只读环境诊断。
powershell -NoProfile -File tools/doctor.ps1
```

构建脚本只设置当前进程的 JAVA_HOME / JAVA_TOOL_OPTIONS / ANDROID_HOME，并写工程的 local.properties。依赖缓存按 Gradle 正常机制使用；不安装 Node 包或全局 CLI。第一次在新电脑编译需要网络下载锁定的依赖。

0.3.0 共 9 个模块，新增 `feature:character` 与 `core:media`。Spine、Filament、Media3 的锁定版本见[版本锁定](版本锁定.md)。Release / Verify 脚本将本次 Gradle 堆设为 4 GiB，并使用 `--no-parallel --max-workers=2`，以降低 R8 同时处理多个媒体运行时的内存峰值；不要同时执行两个 Gradle 构建。该限制不改变系统配置，也不是 App 的运行内存配置。

## Windows 兼容处理的原因

### 双击重新构建出现 `Cannot locate tasks that match ':'`

2026-09-07 已复现并修复。这是 `tools/build.ps1` 的参数类型问题，不是操作失误，也不需要重装 JDK、修改系统或删除缓存。

原脚本将 `switch` 的结果赋给未声明类型的 `$tasks`。Debug / Release 分支只有一个任务时，PowerShell 会将数组输出解包成字符串；随后 `@tasks` 展开原生命令参数，会把 `:app:assembleRelease` 拆成 `:、a、p、p、:……`。Gradle 因而先尝试执行单独的 `:`，报告任务路径缺少名称。多任务 Verify 分支没有这个解包问题，因此“Verify 成功但双击重建失败”可能同时出现。

修复使用 `[string[]]$tasks = @(switch (...) { ... })`，同时固定元素类型和数组形状。新增只读参数回归脚本：

```powershell
powershell -NoProfile -File tools/test-build-arguments.ps1
```

它直接读取生产构建脚本的语法树，检查 Debug、Release、Verify 的真实任务参数，不启动构建。修复后照常双击 `重新构建.cmd`，或执行 `tools/build.ps1 -Target Release`。只有构建成功才覆盖交付 APK 和 SHA-256；失败时“不会更新交付安装包”是保护措施，不是第二个根因。

同一日志中的其他信息含义：

| 日志 | 含义与处理 |
| --- | --- |
| `Picked up JAVA_TOOL_OPTIONS: -Djdk.net.unixdomain.tmpdir=...` | JDK 打印本次进程继承的参数。是下面第 3 项的本机兼容处理，不代表构建失败；不要手动创建 `uds-unavailable`。 |
| `android.overridePathCheck=true is experimental` | 中文工程路径的已知 AGP 提示，见下面第 1 项。它与单独的 `:` 任务无关。 |
| `[Incubating] Problems report is available at ...` | Gradle 生成问题报告的位置，“Incubating”指报告功能的状态；单凭此行不能判断成败。 |
| `BUILD SUCCESSFUL` / `BUILD FAILED` | 最终构建结果。失败时优先查看紧邻 `What went wrong` 的具体异常。 |

### 既有兼容项

1. **中文工程路径。** AGP 路径预检不接受中文，工程没有 NDK/CMake，使用 `android.overridePathCheck=true` 后以实际编译、R8、Lint、安装验证。这不是关闭编译或测试。
2. **Gradle 测试参数文件编码。** 当前 Windows 上 UTF-8 JVM 配置使 Java 测试子进程的中文 classpath 损坏。`org.gradle.jvmargs` 使用 `-Dfile.encoding=COMPAT`，源码和文档仍为 UTF-8。这与 [Gradle 问题 30391](https://github.com/gradle/gradle/issues/30391) 描述的参数文件问题一致。
3. **本机 JDK 的 AF_UNIX 管道失败。** 脚本把 `jdk.net.unixdomain.tmpdir` 指向本工程内一个不存在的目录，让 JDK 使用自身的 TCP 回环回退。不要创建 `uds-unavailable` 目录，不需要关防火墙或改系统网络设置。后续换电脑可先验证是否还需要此兼容项。
4. **AVD 36.1 配置。** 旧 avdmanager 曾生成 android-0 与不兼容图形默认值；仅重建了专用 AVD 的最小配置，显式指定 android-36.1。当前使用已有硬件加速和 `-gpu host`，启动脚本另有 `-Gpu software` 选项。
5. **Windows PowerShell 5.1 中文脚本。** PS1 保存为 UTF-8 BOM；CMD 为 CRLF。脚本没有使用 ExecutionPolicy Bypass，也不会改执行策略。如其他电脑按组织策略禁止脚本，请由该电脑管理者按其规则处理，仍可手动安装 APK。

## 设备自动测试

只在本项目专用模拟器启动后执行。测试使用 Debug 身份，和交付 Release 包的收藏、设置互不影响。

```powershell
. ./tools/environment.ps1
Set-KivoBuildEnvironment
$env:ANDROID_SERIAL = 'emulator-5558'
Assert-KivoEmulator (Join-Path $env:ANDROID_HOME 'platform-tools/adb.exe') $env:ANDROID_SERIAL
./gradlew.bat :app:connectedDebugAndroidTest :core:data:connectedDebugAndroidTest --console=plain
```

完整 UI 用例需要联网读取公开首页与公告 39。网络失败会报告失败，不回退成伪造成功。离线用例需先正常打开并缓存公告列表与公告 39，再通过 `tools/acceptance.ps1 -Mode Offline` 临时断开专用模拟器网络，命令会在 finally 中恢复 Wi-Fi/移动数据。

屏幕与字号专项由同一脚本执行：`-Mode LargeFont` 或 `-Mode Tablet`。这会临时改变专用 AVD 的字体/显示覆盖值，结束后恢复。不会改变 Windows 显示设置或手机设置。

角色专项使用 `tools/character-acceptance.ps1`，四种模式为 `Phone / LargeFont / Tablet / Offline`。覆盖六类角色、图鉴查询与视图持久化、Markdown 对齐、GIF、语音、Spine 立绘／大厅及人物／光环原生渲染、编码导出和后台暂停。Offline 先缓存公开样本，断网后另行断言 `activeNetwork == null`，再打开资料及四类媒体。表态／补充写入在 `FoundationStorageTest` 和 `NetworkContractTest` 中用受控服务验证，不向生产站点发送测试写入。

测试 XML 在各模块 `build/outputs/androidTest-results`，单元测试报告在 `build/reports/tests`。交付时保留的证据摘要见 [验收报告](../artifacts/验收报告.md)。

Release 的额外检查使用 `node tools/release-smoke.mjs`，只操作该专用模拟器与 preview 包：安装、进程冷启动、公开公告收藏、后台进程恢复、同签名覆盖安装，以及压缩后的原生角色媒体。`node tools/inspect-apk.mjs` 只读交付 APK 并检查 ELF 对齐。更新证据后用 `node tools/build-character-report.mjs` 生成 0.3 图册与报告；生成器核对 APK 摘要和测试失败数，拒绝使用不匹配的旧证据。两个旧报告脚本仅保留历史用途，遇到其他版本会拒绝覆盖。

模拟器测试区分进程和任务：`force-stop` 不保证丢弃 Android 保存的任务状态。测“全新启动偏好”时同时使用 `NEW_TASK | CLEAR_TASK`，测“后台进程恢复”时保留任务；二者都不清应用数据。Release 脚本开始时通过正常设置入口准备首页偏好，便于上次中断后重新运行。

持续更新的首页可能使系统 `uiautomator dump` 一直等不到空闲；部分版本甚至返回 exit 0 并保留旧 XML。当前 Release 检查改用 `ReleaseUiSnapshotTest` 只读桥读取即时可访问树，再等待实际目标与选中状态。它运行于独立 Debug 测试进程，不创建 Activity、不修改 Release 数据，默认套件中按参数跳过，不计入业务通过数量。第一次执行 Release 检查前先构建 `:app:assembleDebug :app:assembleDebugAndroidTest`；脚本只向专用 AVD 安装这些测试包。

## Android Studio 与其他电脑

Android Studio 直接打开 `App项目开发`。Gradle JVM 选择 JDK 21。当前机器如从 IDE 构建仍遇到 AF_UNIX 问题，可先在设置好上述进程环境的终端启动 IDE，或使用已经验证的 `重新构建.cmd`；不需要永久改全局 Java 环境。

其他电脑先用 Android Studio SDK Manager 安装对应 SDK、Build Tools 和可用系统镜像，再配置自己的 local.properties。模拟器镜像是开发工具，不放入 APK，也不应把本机大型缓存视为源码依赖。不同设备基线须记录具体版本后重新测试。

版本的唯一修改入口是 `gradle/libs.versions.toml`，模块只引用目录别名。核心平台和包装器版本分别在构建文件与 `gradle/wrapper/gradle-wrapper.properties`。禁止动态 `+`、SNAPSHOT 和未经验证的全量升级。

根构建开启 `dependencyLocking.lockAllConfigurations()`。每个模块的 gradle.lockfile 保存传递依赖解析结果，根和构建脚本锁也保留。变更依赖时执行受影响配置的成功构建并带 `--write-locks`，审查差异后跑检查；**失败的 Gradle 任务不会可靠写入锁文件**，不要以失败测试当作锁已更新的证据。

Espresso 显式升级是一次兼容修复：旧测试依赖 3.5.0 在 Android 36.1 的输入管理接口上崩溃；3.7.0 修复该问题，当前设备 UI 测试已经通过。[官方 AndroidX Test 发布记录](https://developer.android.com/jetpack/androidx/releases/test)

API 37 编译和目标行为依据 [Android 17 官方资料](https://developer.android.com/about/versions/17) 和 [AGP 9.2 发布记录](https://developer.android.com/build/releases/agp-9-2-0-release-notes) 确定。当前实际设备镜像为 Android 16 / API 36.1；没有把编译版本写成设备覆盖结果。

0.3.0 引入表中 Media3、Spine、Filament；大图分块使用 Android BitmapRegionDecoder，没有额外第三方图片运行时，也没有引入 WorkManager。原生库 ABI、包体与 16 KiB 对齐以本期 APK 检查为准。

发行包使用独立验收包名及本机测试证书。正式版本需要明确身份、私有签名与迁移安排；不能把测试证书复制到公共仓库。交付 APK 的实际摘要、签名验证和大小见验收报告。
